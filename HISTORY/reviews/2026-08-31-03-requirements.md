# Review 3 -- the requirements auditor

**Date:** 2026-08-31, **Standpoint:** somebody holding a copy of the retired
design brief, checking clause by clause whether this tree actually contains
what the brief required -- not whether a table *says* it does.

**What I looked for:** a requirement that survived as a row in the coverage
table and died on the way to the file that row names. The coverage table is the
document a later session trusts *instead of* re-checking, so an error in it is
strictly worse than an error anywhere it points.

---

## Method

Four passes, mechanical where possible, because *"I read it and it looks
complete"* is exactly the assurance this project does not accept.

1. **Heading census.** Every heading in both retired documents, matched against
   every row of the coverage table, in both directions.
2. **Normative sweep.** Every `MUST` / `MUST NOT` / `MUST NEVER` / `SHOULD` /
   `DECIDE` / `RECOMMENDED` occurrence in the brief -- 107 of them -- with the
   first five words after the keyword searched for across the tree.
3. **Requirement-at-target.** For 41 load-bearing requirements, open the file
   the coverage table names and confirm the requirement is *there*, by a phrase
   that would not survive it being dropped.
4. **Enumeration completeness.** The brief's fourteen five-year questions
   against T-083; its twenty-item experiment programme against T-030; its six
   scoring invariants; its five categories.

---

## What it found

### 1. The coverage table over-reported itself -- **fixed**

It claimed **"101 of 101"** brief sections mapped, and said the mapping "was
generated by walking the headings of the actual files rather than from memory".

The brief has **97** headings. Four rows named sections that appear in neither
retired document -- *"What round 1 actually corrected"*, *"What is still
unverified and load-bearing"*, *"Weaknesses in the evidence that now exists"*,
*"Weaknesses that no amount of measurement will fix"*. The count was inflated by
exactly those four, so the generator claim was false for them.

**Fixed:** four phantom rows removed, count corrected, and the correction
recorded in a box at the top rather than made silently. Re-verified in both
directions: 97 of 97 headings have a row, and no row names a section that does
not exist.

### 2. The brief's auditability invariant had no rule -- **fixed**

The brief's pipeline invariants include *"Every accept/reject decision is
auditable after the fact."* Eight places in `src/` cited the brief's section 11 for it. The
word "auditable" appeared **nowhere** in `RULES.md` or `docs/AGENTS.md`.

So the invariant that makes `parse_many` return its rejections rather than log
them, and `Aggregate` carry `provenance`, was load-bearing in the code and
absent from the rules. **Fixed:** RULES 3.10, with the reason and the concrete
consequence (a rejection is a returned value, never a log line, because a
warning a caller can ignore will be ignored).

### 3. The documentation standard bound the wrong thing -- **fixed**

*"Documentation MUST be concise, technical, evidence-backed, reproducible, and
organized as usable manuals. No project lore, no history dumps in reference
pages."*

Present -- inside `TODO/docs.md`, as part of an **open entry** about a
documentation set nobody has written. So it constrained the future documents and
not the ones that exist, which is exactly backwards for a standard.
**Fixed:** RULES 17, which also carries the cold-start test verbatim and the
rule that no session writes a kickoff prompt for the next.

### 4. Eighteen entries cited themselves as their own source -- **fixed**

`T-080`'s `Source:` was "T-080". `T-063`'s was "T-063; decision D5".

They came from a substitution pass that rewrote the brief's section number into
the id of the entry replacing it -- **destroying the provenance that the whole
retirement exercise existed to preserve**. Provenance is the argument for
retiring the brief at all; eighteen entries had none.

**Fixed:** each names its brief section, and `check-todo.py` now fails on a
`Source:` beginning with the entry's own id -- which caught six more on its first
run than the exact-match version did, including `T-030, items 3-18`.

### 5. Thirty-three bare section references -- **fixed**

The first repair pass matched the qualified form and missed the bare one,
which resolves to nothing at all. `check-citations.py` now rejects a bare section number unless the line frames
it as provenance (*"the brief's section 8.2"*).

**And my first attempt at that repair was worse than the disease.** A blind
substitution made `normalize.py`'s docstring cite itself, turned a reference's
*own* section 9 into "RULES 4", and had `model.py` claim RULES 3.1 had
tabulated something written before RULES existed. Reverted whole and redone one
line at a time. Recorded as correction 17, because it is the same defect --
*a tool answering confidently where it should have failed* -- committed by the
session repairing that class of error.

---

## What passed

**Normative sweep: nothing dropped.** All 107 normative statements are
represented. Fifty-eight did not survive as a verbatim five-word phrase, and
each was checked by hand: every one is present in reworded form at the place
the coverage table names. Rewording is allowed; dropping is not.

**Requirement-at-target: 41 of 41.** Every load-bearing requirement is
*actually in* the file its row names -- the six health states, the three dedup
questions, the seven ladder rungs, `numwant=0`/`event=stopped`, the politeness
ceiling, decompression bombs, "no random query parameters", "history lives in
files", the six scoring invariants, all five categories including Fosstorrents,
cross-format consistency, atomic publication, "one pathological tracker must
not consume the runner", "never recover by deleting valid data", the injected
clock, "no large empty directory tree", and all twelve Appendix A
anti-patterns down to captive portals.

**Enumerations are complete.** T-083 carries all fourteen five-year questions.
T-030 carries all sixteen unrun experiments (3-18) with what each feeds.
Twenty-four of 24 operating-contract sections map. All 43 original claim-register
rows migrated, and 26 have been added since.

---

## What I looked for and did not find

* **A `MUST` softened to a `SHOULD`.** None. The four the retirement review
  restored are still in their explicit normative form.
* **A requirement closed as "won't fix" or "out of scope".** None --
  `check-todo.py` fails on those strings, and it has never had to.
* **A `DECIDE` that vanished.** All six of the brief's became decisions or
  entries; five more have been added since (D7-D11).
* **An entry with no acceptance.** `check-todo.py` fails a `done` entry with no
  `**Done.` paragraph; it caught one during this session and none remain.

## What this review did NOT establish

* **That the mapping is the best one.** A section routed to a rule might have
  been better as an entry. The rows are reviewable and I reviewed them for
  *presence*, not for *placement*.
* **That the requirements are right.** The brief was written from partial
  information and says so; eight of its claims are already refuted. This checks
  fidelity to it, which is a different question from whether it was correct.
* **That an implemented requirement works.** Most of these are open entries.
  Being *represented* is what the coverage table promises, and it is all this
  review confirms.
* **That the four phantom rows were the only fabrication.** They were the only
  one a heading census can find. A row that names a real section and points at
  the wrong place would pass that census, and pass 3 above checked 41 of 97
  such rows by hand -- not all of them.
