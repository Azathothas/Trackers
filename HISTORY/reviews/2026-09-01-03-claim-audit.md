# Review 3, the claim audit

**Date:** 2026-09-01. **Standpoint:** somebody who has read every document
written this session, believes none of them, and wants to re-derive each
number from the tree.

**What I looked for:** a sentence written this session that is not backed by
something on disk. ⛔ **A summary is a claim like any other**, and this session
produced roughly 5000 lines of new prose, most of it asserting things about a
tree that was changing underneath it.

**What I did not look at:** the documents this session did not write. The
previous session's claim audit is
[`2026-08-31-02-auditor.md`](2026-08-31-02-auditor.md) and its findings are in

## Findings

### 1. ⛔ The headline number of this session's largest change was wrong, in three places

Three documents said the tree had carried **1213 characters** outside the
allowed five, **741 of them em dashes**, with **27 violations in `src/` and
`tests/`**. Every one of those figures was wrong, and they were wrong in the
way that is hardest to catch: **they came from an instrument, and I read the
wrong field of its output.**

`check-markers.py` reports the **first offender per line**. So 1213 was a count
of offending *lines* on the tree it judges, 741 was the number of lines whose
first offender happened to be an em dash, and 27 came from miscounting a
truncated report.

Re-derived against the tree as it stood at the first commit of this session,
counting characters rather than lines:

| | measured |
| --- | --- |
| files with at least one violation | **55** |
| offending lines, raw | 1237 |
| offending lines as `check-markers.py` counts them | 1213 |
| ⭐ **characters outside the five** | **1655** |
| em dashes | **840** |
| files under `src/` or `tests/` | **14** |

⚠ **A line count and a character count are different numbers and neither is a
substitute for the other.** All three documents are corrected, and
`check-markers.py`'s own header now says which of the two it reports, so the
next reader cannot make the same substitution.

⭐ **This is the finding that justifies the pass.** Nothing mechanical would
have caught it: the number came from a real instrument, the instrument was
right, and the prose around it described a different quantity.

### 2. The character check exempted one of this project's own files

`scripts/_scope.py` exempted `references/` wholesale, on the correct reasoning
that a captured upstream tree is byte-exact evidence nobody may edit. ⚠ **That
also exempted `references/PROVENANCE.md`**, which is this project's own writing
about the corpus and is not anybody else's source. It sat outside the prose
rules through the whole migration and still carried the characters the rest of
the tree had been cleared of.

**Found by reading a grep hit for a number**, not by any check, which is the
point: an exemption is invisible to the guard it exempts from.

**Fixed.** The exemption is now per captured repository, matched as
`references/<owner>__<repo>/` by shape rather than by a list, so a sweep that
adds an eleventh reference needs no edit and cannot be forgotten. The file was
then migrated like every other, and two further defects fell out of it: a
shell-unsafe placeholder in a block a reader is meant to paste, and a sentence
duplicated into `TODO/claims.md`.

### 4. Two claims I repeated from this project's own record without re-deriving them

⚠ **Stated because repeating a number is how one becomes load-bearing without
anybody measuring it.**

- **"374 broken citations on its first run"**, in `scripts/README.md` and
  `docs/methodology/reviews.md`. That is the previous session's figure, taken
  from [`../corrections.md`](../corrections.md). It cannot be re-derived: the
  tree it was measured against has been fixed. It is attributed rather than
  presented as this session's measurement.
- **"111 corpus files dropped from every clone"**, in several places. Same
  shape, same source, same limit.

Neither is load-bearing for anything built this session. Both are cited to the
record that owns them rather than restated as fresh.

### 5. A claim in the README that the tree could not support, and the re-measurement that fixed it

The README used to open its measurement section with the runner figures: UDP
egress, BEP 15 connect rates, IPv6 egress. **Those results were not in the
tree.** They belonged to a workflow run whose artefacts went with this
repository's prior history.

⛔ **Quoting them would have been the exact defect this pass exists to catch:**
a number on a public page with no instrument output behind it. The README now
states the constraint qualitatively and points at the file that owns each
figure.

⭐ **The baseline was then re-taken rather than left as a gap**, on workflow run
`33383406869`, and the figures in `PROGRESS.md` and `TODO/foundation.md` are
that run. ⚠ **Every one of them differs from the number this file used to
carry**, which is the argument for re-measuring rather than restating: BEP 15
connect is 10/11 rather than 9/11 because one target has no IPv4 address and
was being counted as a failure of the tracker, the median RTT moved from
109-127 ms to 97.5-103.9 ms, and HTTP discrimination is 4 of 6 rather than 5 of
6.

⚠ **And the DNS figure disagrees with itself between two runs 40 minutes
apart**: 1 divergent, then 0. Both are recorded. One run of two is not a
measurement of divergence, and T-007 exists because of exactly that.

## What would have made this pass fire harder

It fired twice, so the question is what it still cannot reach.

⚠ **It cannot check a claim about the future**, and this session wrote several:
that the ceiling in `check-no-secrets.py` will come off when `T-107` closes,
that the `expect_skip` flag will come off when P2 lands, that the lost baseline
will be re-taken. **Each of those is a promise with nothing enforcing it.**
Review 2 names the cheapest mechanical fix for one of them; the other two are
entries.

⚠ **It cannot check tone.** Every document here was written in one session by
one author, and the claim that they read as a coherent set is the one sentence
in this review with nothing behind it.
