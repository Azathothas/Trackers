# Review 2 -- the auditor who distrusts the author

**Date:** 2026-08-31, **Standpoint:** somebody who has read the documents,
believes none of them, and wants to re-run every load-bearing claim without
asking anyone. The methodology's own test, applied to this repository:

> **Could somebody who distrusts you re-run every load-bearing claim without
> asking you anything?** If not, the sweep is an opinion with citations.

**What I looked for:** a claim whose evidence has evaporated -- an instrument
that is gone, a corpus that must be re-fetched, a test that passes whether or
not the thing it names is true.

---

## Method

1. **Mutate the code and see whether the suite notices.** A test that does not
   fail when the claim stops being true is not evidence (RULES 1). Six
   mutations, chosen to break the invariants the project's correctness rests
   on.
2. **Audit the register.** Every `VERIFIED` row: does its *verify by* column
   name something a reader can actually reach?
3. **Audit reachability.** Is the corpus complete enough that no claim needs a
   fetch to check?

---

## 1. Mutation testing -- one invariant was not defended

| # | mutation | suite |
| --- | --- | --- |
| M1 | `UNSUPPORTED_TRANSPORTS` emptied, so `wss` becomes measurable | **failed (1)** ✅ |
| M2 | `scrape_url`'s path-component anchor removed, so it guesses again | **failed (2)** ✅ |
| M3 | the execution-profile default flipped from `ci` to `local` | **failed (7)** ✅ |
| M4 | `min_interval`'s underscore spelling dropped | **PASSED** ⛔ |
| M5 | `normalize`'s hostname validation removed, so a U-label is accepted | **failed (2)** ✅ |
| M6 | the two `min interval` spellings' precedence reversed | **PASSED** ⛔ |

**M4 and M6 are the finding.** The `min interval` handling added earlier the
same day -- the tracker's stated *floor*, which D7's politeness anchor depends
on -- could be removed or silently reordered and nothing complained. It was
code with a citation and no test, which is the shape this project's own RULES 1
calls not-evidence, written by the session enforcing that rule.

**Fixed.** `tests.test_probe.TrackerStatedInterval`, four tests: both spellings
read; an absent floor is `None` and never `0` (an absence is not a zero, in the
inbound direction); a non-integer floor is rejected rather than coerced,
because upstream bodies are hostile input; and BEP 3's spelling wins
deterministically when a tracker sends both, because a tie resolved by dict
order is not determinism. **M4 and M6 both fail now.**

## 2. The register -- two rows were weaker than they read

Of 63 rows, 42 are `VERIFIED`. Thirteen have a *verify by* column that names no
path -- but eleven of those are legitimately verified by reading a specification
(BEP 3, 15, 20, 48) or a corpus line, and those corpus lines are now pinned in
`experiments/fixtures/load-bearing-citations.tsv`, so a script re-checks them.
Two were not fine:

**`C-28` cited a commit the corpus no longer holds.** It said TEMPLATE's
methodology docs were verified "cloned at commit `6eaf4b5`"; the re-mine moved
the tree to `6206166`, so a reader following the row would have looked for a
tree that is not there. Now names both, and states what changed between them:
the three documents this project's rules rest on are **byte-identical**, and
`references.md` gained one paragraph.

**`C-43` had become true-but-misleading.** It concluded "a plain descriptive
User-Agent sufficed", which is still true of *source fetches* and is no longer
true in general -- `C-64` records an intermediary refusing exactly that string
while accepting `curl/8.5.0` in the same second. A row that reads as settled
when its neighbour has weakened is how a reader stops checking. Now
carries the qualification and points at the shortlist if it changes.

## What I looked for and did not find

* **An orphaned instrument.** Every numbered experiment is present; none is
  cited and missing.
* **A claim resting on a deleted corpus.** None. The trees are in-tree, which
  is the whole argument for keeping them there.
* **A test asserting on a mock of the thing under test.** The probe is measured
  against `tests/fake_tracker.py`, an oracle of servers we control that speaks
  real BEP 15 and real bencode -- measurement from outside, not a self-report.
* **A number in the documents that no instrument produced.** The retired-figure
  gate covers the ones that existed; the test-count gate covers the one class
  that had drifted twice. I did not build a general one, and a general one is
  not evidently possible.

## What this review did NOT establish

* **That the six mutations are the right six.** They were chosen by me, over
  code I had written in the same session, which is the weakest possible sampling. A reviewer
  without that bias would pick differently and should.
* **That the `VERIFIED` rows are true.** I checked that each names something
  reachable, not that re-running it reproduces the stated result. Doing that
  properly means re-running the runner experiments, which needs CI.
* **That the corpus is complete.** Four trackers unfetched, discussions
  unfetched everywhere, review comments unfetched everywhere, two trackers
  truncated at 100 items, and six comment threads that no available route
  returns (`C-67`). All named in `PROVENANCE.md`; none closed.
