# Review 1 -- the cold start

**Date:** 2026-08-31, **Standpoint:** a session handed exactly one
instruction -- *"Read `docs/AGENTS.md` in full and follow"* -- with no memory, no
context, and no operator to ask.

**What I looked for:** the point at which that session would be stopped,
misled, or forced to guess. Not whether the documents read well; whether
following them mechanically produces work.

---

## Method

Three passes, each asking a different question (the reference methodology's own
rule, applied to ourselves):

1. **Does every documented command run?** Every `python3 ...` in
   `docs/AGENTS.md` and `README.md`, executed, exit code recorded.
2. **Does every structural claim hold?** Every directory, module, workflow and
   count those two files name, checked against the tree.
3. **Where does the route dead-end?** Follow the reading order as written and
   find the first place a reader has to supply something the tree does not.

## What it found

### 1. `experiments/results/` was hoarding indistinguishable re-runs -- **fixed**

Ten committed runs of the offline scheme census, all reporting the same
numbers, differing only in a timestamp. Six of the platform-contract check,
three of them minutes apart.

This is a misreading of RULES 2's *"it does not clean up its own output"*. That
rule stops an **experiment** deleting its own evidence. It does not make the
repository a landfill, and the cost is real: a reader opening `results/` to
find the census answer sees ten files and has to work out which one to believe
-- which is the same shape as the problem that produced
[`corpus-baseline.md`](../corpus-baseline.md).

**Fixed** by naming the distinction that actually decides it -- *is this
reproducible on demand?* -- in `experiments/README.md`, and pruning to it. Every
runner result and every networked result is kept, because those moments do not
come back. Offline runs against pinned fixtures keep the first (documents cite
it) and the most recent (it shows the instrument still runs); the eight in
between are regenerable by a command in that file.

### 2. Two vestigial `.keep` files -- **fixed**

Two `.keep` placeholders under `.github/`, in directories that have
contained real workflows since P0. RULES 14 says a directory earns its
existence by containing something; both did, and the placeholders outlived
their reason. Removed.

### 3. The README contradicted RULES 4.1 outright -- **fixed**

The README said, under obligations to tracker operators:

> **It identifies itself.** Every request carries a User-Agent naming the
> project and its URL, so an operator who objects can find us.

RULES 4.1 **withdrew exactly that**, in detail, with the reasoning. So the
document a *consumer* reads promised a policy the document a *contributor*
reads had retracted -- and the consumer-facing one is the one that looks like a
commitment to an operator.

Worse than a stale sentence: it is a promise about behaviour toward third
parties, made in the file most likely to be read by one of them. Rewritten to
state the open question, the line that does not move (never evade an exclusion
already given), and the entry that will settle it.

### 4. The route to a corpus number had no signpost -- **fixed**

The reading order sent a session to `PROGRESS.md`, `RULES.md`, `INDEX.md` and
`claims.md`. None of those is where corpus figures live, and the session that
needed one would have found them restated -- differently -- in three places. The
reading order now names
[`corpus-baseline.md`](../corpus-baseline.md) explicitly, with the reason.

## What I looked for and did not find

Said explicitly, because a review that reports only what it found has not shown
where it looked.

* **A command that needs the network to pass a gate.** There is none: every
  gate runs offline, which is what makes "it works on my machine" checkable.
* **A step requiring a credential.** None. The proxies carry none, and the
  corpus tools are read-only.
* **A platform assumption.** Every gate is `python3 scripts/*.py`; no gate
  shells out, so a Windows or Podman contributor runs the same commands. I did
  not *execute* on Windows -- that is unavailable here and is stated as such,
  not assumed away.
* **A place the reading order loops.** `AGENTS.md -> PROGRESS.md -> RULES.md ->
  INDEX.md` terminates, and each says what it is for.
* **A contradiction between `AGENTS.md` and `RULES.md`.** The map restates
  nothing normative; it links. That is what stops them forking, and it holds.

## What this review did NOT establish

* **That the work order is the right one.** I checked that a session can
  follow it, not that following it is the best use of a session.
* **That the entries are correct.** I checked that every id resolves and every
  count derives, not that any entry's premise is true.
* **That the *documentary* cold start works.** I am not a cold start -- I have
  this session's context, so I cannot honestly judge whether `AGENTS.md` alone
  is enough for a reader who does not.

**What was done after this review was written**, because the review's own gap
turned out to be the session's most expensive defect: the pushed head was
cloned into a fresh directory and every gate run there. All gates green,
`generate --offline` and `TRACKERS_PROFILE=local` both clean. **That check is
now RULES 10.3 step 9**, with the command, because the six red CI runs this
session produced were all one instance of a tested tree and a committed tree
being different (`corrections.md` 18).

**And it was still not enough, which is the finding worth keeping.** That run
reported the clone's file count as evidence it was whole. It was not: the clone
was **111 corpus files short**, and every gate passed anyway, because no cited
line happened to sit in a dropped file (`corrections.md` 23). Running the gates
on a clone answers "do the gates pass there", not "is the clone the same tree".
The second question needs its own instrument, and now has one --
`scripts/check-corpus-integrity.py`, plus the corpus diff in RULES 10.3 step 9.
A count quoted from a passing run is not a check; it is a number that was
present when nothing complained.
