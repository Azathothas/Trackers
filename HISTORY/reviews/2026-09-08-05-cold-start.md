## Finding 1 -- the work order sends a cold session at a command that does not exist

**T-012 is item 4 in the work order.** Its `Prove` clause reads
`python3 experiments/26-user-agent-block-rate.py --expect-arms` (planned), and
that file **does not exist**. It was not marked `(planned)` at the time.

⛔ **`check-citations.py` is the gate for exactly this and it passed**, because
of a hole in its own scope: it skips any backticked token containing a space.
**Every `Prove:` clause in `TODO/` is a command, and every command contains
spaces**, so the entire class of "the entry tells you to run something that is
not there" was outside the check.

**How a cold session hits it:** read the router, read PROGRESS, take item 4,
run its `Prove` command, get `No such file or directory`. Nothing in the tree
would have said which of the two -- the entry or the file -- was wrong.

**Fixed both ways.** The clause is marked `(planned)`, and
`check-citations.py` now splits a backticked command and checks each word that
looks like a repository path, with the same `(planned)` / `(removed)` escapes
applied per line. Mutation-proved: removing the marker returns exit 1 naming
the path.

⚠ **The fix found a second defect while being tested** -- the marker had been
appended twice on one line, so removing one left the other and the guard stayed
quiet. A guard proved against a fixture that was itself wrong proves nothing,
which is why the lens says to read the exit code rather than the pass count.

## Finding 2 -- the gate was red on the pushed head, for the second time today

The clone's `check-gate.py --strict` failed on `check-markers`: an em-dash in
the review committed twenty minutes earlier.

⛔ **The cause is identical to the first occurrence and that is what makes it a
finding rather than an accident.** Both times: the gate was run, it passed, one
more edit landed, and the reading was not repeated. Neither was carelessness
about the rule -- both commit messages quote a real gate run.

**Fixed structurally.** `scripts/install-hooks.py` installs a pre-commit hook
running `check-gate.py --fast`, which catches every failure both red commits
had. ⛔ **It is opt-in and never automatic**, because a hook is a change to
somebody's working copy that outlives the session, which
[`../../docs/agent-tooling.md`](../../docs/agent-tooling.md) names as the first
reflex to stop. It refuses to overwrite a hook it did not write.

⭐ **And the hook broke on the hazard this repository already documents.** Its
first version used `command -v python3`, which succeeds on this Windows host
because the Microsoft Store stub **is** on `PATH` -- and then fails to run.
`docs/conventions/shell.md` section 6 states that in so many words: *presence
is not capability; probe by running the tool, not by finding it.* The hook now
runs `python3 -c ""` and falls back to `python`.

## Finding 3 -- a local `git reset --hard` discarded a pushed commit

While testing that the hook blocks a red commit, the commit was correctly
**refused** -- so `HEAD` had not moved, and the `git reset --hard HEAD~1` meant
to undo it removed the previous commit instead, which was the pass-4 review.

⚠ **Recoverable only because it had been pushed**: `git reset --hard
origin/main` restored it. Had it been local-only it would have been gone.

⭐ **The general shape is worth more than the incident**: undoing a command
that may not have run is a reset relative to a position you have not checked.
`docs/conventions/git.md` already forbids rewriting *published* history and
says nothing about local resets, which is correct -- the rule that would have
prevented this is reading the exit code before acting on it, which this
repository states for pipes and not for this.
