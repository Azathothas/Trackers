# 2026-09-05, review 2: what other door reaches this code

Lens 1 of [`../../docs/methodology/reviews.md`](../../docs/methodology/reviews.md).

**The question:** the session added a consent gate before contacting a tracker
and a refusal before publishing a credential. **What else reaches those two
actions?**

⭐ **Review 1 could not have found either finding below**, and that is the
argument for three lenses rather than one deep one. Review 1 attacked code I
had written. Both findings here are in code I did **not** write this session,
reached by asking what else arrives at the same place.

Method: enumerate the affordances from memory, then grep for the callers the
list left out. The list written from memory was not complete, again.

## Found: two instruments contact trackers with no consent check

**Severity: high. It is a conduct defect, not a correctness one. Fixed here.**

`src/trackers/probe.py` consults BEP 34 before opening a socket, and I treated
that as "the project honours exclusions". Grepping every socket in the tree
says otherwise:

```
src/trackers/bep34.py     the lookup itself
src/trackers/probe.py     gated
src/trackers/vantage.py   routing-table lookup, sends nothing
src/trackers/acquire.py   fetches source lists, not trackers
experiments/02, 05        contact real trackers, consult NOTHING
```

`grep -ln "bep34\|BEP 34" experiments/*.py` returns nothing, exit 1.

⛔ **And it is not hypothetical.** `p0-ground-truth.yml` triggers on
`paths: experiments/**`, and this session pushed two commits touching that
directory. Both fired:

```
2026-09-05T02:20:51Z  4566989  completed/success  33938811758
2026-09-05T02:12:06Z  7cfd16a  completed/success  33938397308
```

Each run probes 11 UDP and 6 HTTP endpoints on two runner images. **So this
session built the exclusion gate and then contacted trackers through a door
that bypasses it, twice, hours later.**

⚠ **No operator's refusal is known to have been violated, and that is luck
rather than the gate working.** Checked after the fact against the 17 pinned
subjects: all 17 are permitted today, none publishes a denial. That was checked
today and the runs were today, which makes it good evidence and not proof of
the state at 02:12.

**Fixed** by `experiments/_consent.py`, which imports `src/trackers/bep34.py`
rather than reimplementing the lookup -- a second copy of a consent check is
two places for it to be wrong, and the copy nobody reads is the one that keeps
probing. Both instruments now skip a refused subject and record it under
`refused_by_bep34`, separately from failures: **a subject we may not measure is
not a subject that failed.**

## Found: T-020's acceptance claims a shared codec that is not shared

**Severity: medium. Recorded, not fixed here.**

[T-020](../../TODO/measurement.md)'s closing paragraph says:

> The codecs were lifted into `src/trackers/bep15.py` and
> `src/trackers/bencode.py` so the experiments and the production path are the
> same code and cannot drift.

They are not the same code. `experiments/02-udp-bep15-connect.py:89` defines
its own `build_connect_request` and `:94` its own `parse_connect_response`,
alongside `src/trackers/bep15.py:91` and `:96`. No experiment imports from
`src/` at all -- every one of them puts only its own directory on `sys.path`.

So the codecs were **copied**, not lifted, and the entry's own justification
for closing is false. ⚠ This is the exact pattern that entry claims to have
prevented: two implementations, and a fix to one never reaching the other.

Not fixed here because unifying them is real work with its own risk -- the
experiments' committed results are evidence taken by *that* code, and swapping
the codec underneath them changes what a re-run means. It is recorded on
T-020 as a correction under its title (RULES 7) with a new entry to do the
work.

## Held: the credential refusal has one other door, and it is guarded

`carries_private_credential` is called from `pipeline.aggregate` and from
`generate.verify`. `render_plaintext` -- the single write path for the
published format -- does **not** check, and it is public and takes any
`list[Tracker]`.

**What would have had to be true for this to fire:** a caller that renders
trackers it did not get from `aggregate`. There is one today,
`tests/test_p1.py:375`, rendering a manual list with `preserve_order=True` --
which is the `hardcoded.txt` path [T-046](../../TODO/scoring.md) needs and
[T-106](../../TODO/sources.md) has no input file for yet.

So the hole is not reachable today and becomes reachable the moment
`hardcoded.txt` gets content. Recorded on T-106 rather than fixed, because the
fix belongs with the file that creates the risk.

## Held: nothing reaches a socket around the sweep's bounds

`probe_udp` and `probe_http` are the only tracker sockets under `src/`, both
gated, and `sweep` is the only caller that opens many at once. `probe-corpus.py`
is the only script that drives `sweep`. **What would have made this fire:** a
second runner, or a script calling `probe` in a loop of its own. Neither
exists; `grep -rn "probe(" scripts/` returns only `probe-corpus.py`.
