# 2026-09-05, review 5: a session handed only the router

**The question:** a session with no memory is told *"Read `docs/AGENTS.md` in
full and follow"*. **Where does following it mechanically stop working, and
what did this session add that a reader has to wade through?**

⭐ **This lens exists because of what happened earlier the same day.** The four
passes before it examined code and claims. This one examines the *instructions*,
and the session it is reviewing is the evidence: I read the routing table, then
failed in a way `methodology/reviews.md` describes in advance -- in the file the
table would have sent me to, had I looked at it again.

---

## Found: the routing table reads as a start-of-session step

**Severity: high, and it is upstream of the worst defect this session shipped.**

`AGENTS.md` section 3 is "Start of session, in order", and its step 4 is *"read
what section 4 routes your task to"*. Section 4 then says to find the row for
"the work in front of you". Nothing says to come back.

So the table is consulted once, for the task the session believes it has. This
session began by working an entry, took the `Working an open entry` row, and
never took the `Reviewing, or closing out a session` row -- which names
[`../../docs/methodology/reviews.md`](../../docs/methodology/reviews.md), the
page carrying:

> ⚠ The task list is never the enumeration. It has never once contained them all.
> ⭐ **grep for the ones you did not enumerate.**

That is review 2's finding stated in advance. The ungated experiments would
have been found hours earlier by the page the router names for a task the
session was, by then, actually doing.

**Fixed** in section 4: *"Come back to this table when the work changes shape,
not only at the start of a session."*

⚠ **A rule nobody re-reads is not fixed by adding a sentence**, and this one is
prose rather than a check. It is recorded here so the next session that skips a
row knows the defect is known and the mechanism is not.

## Found: this session put narrative history into three reference pages

**Severity: medium. Fixed.** RULES 17: *"No project lore and no history dumps
in a reference page. A page that answers a question answers it; what it used to
say belongs in `HISTORY/`."*

| page | what it had grown |
| --- | --- |
| `README.md` | a paragraph opening *"An earlier version of this section said..."*, recounting a correction made hours earlier |
| `docs/agent-tooling.md` | a `gh` row explaining what the row used to say and which entry that would have blocked -- on a page whose own contract is "names, links and one line each, and nothing else" |
| `scripts/README.md` | a table row carrying the design argument for why one script has no offline mode, which its docstring already carries |

⛔ **All three were written by the pass that was supposed to be enforcing the
rule.** Corrections are owed to the reader in `HISTORY/`, where reviews 2 and 4
already carry them; a reference page owes the reader what is true now. The
README is the sharpest case: RULES 17.1 says a human reads it once and stops,
and a correction notice is a changelog wearing a manual's name.

A fourth page, `docs/conventions/shell.md`, took a new entry legitimately --
that page *is* a catalogue of measured traps -- but at 18 lines it was longer
than its neighbours and is now 15.

Net documentation growth for the session, after the trim: **76 lines across 5
files**, all of it constraint or instruction rather than account.

## Held: the cold start still works, mechanically

Walked as a session with no memory:

1. `AGENTS.md` names `PROGRESS.md`, `RULES.md`, `check-gate.py`, section 4.
2. `PROGRESS.md` opens with the state, the baseline with each figure's owning
   file, and an ordered work list with entry ids.

   *directory* is refused because git does not track one.
4. The Windows note in section 3 is the one that decides whether step 3 runs at
   all, and it is where a reader hits it rather than three pages away.

**What would have made this fire:** a work-order item naming an entry that no
longer exists, a baseline figure with no owning file, or a routed page that
does not resolve. The first two were checked by hand against `INDEX.md` and
`corpus-baseline.md`; the third is mechanical.
