## Finding 1 -- `select()` had two callers and one was silently authoritative

**Found before the sweep, by needing a denominator; recorded here because it is
the same class.** `scripts/probe-corpus.py` sampled the corpus and handed the
*sample* to `sweep()`, which records `corpus=len(trackers)`. So the committed
record of run `33938543488` says `corpus: 200` against a corpus of 1327, and
`counts.corpus` and `counts.selected` -- the pair whose entire purpose is to say
"200 of 1327" -- were the same number.

**Why it survived:** `select()` is idempotent at that boundary, so the sample
was never wrong and no health state moved. Only the denominator was affected,
and a wrong denominator is the half that gets divided by rather than argued
with.

**Fixed.** `sweep()` selects and the script previews.
`tests.test_concurrency.TheSweepScriptReportsTheCorpusItSampledFrom` is the
regression test; mutation-proved by putting the defect back (exit 1). The
committed record is **not** rewritten -- the correction is under T-024's title.

## Finding 2 -- the credential rule bound the pipeline and not this project's own writing

**Not on the list.** `PRIVATE_CREDENTIAL` matched `passkey=` and a long path
component and did not match `authkey=<id>|<id>|<token>`, a shape two corpus
URLs use. Trying to redact one returned it unchanged.

**The door that was open:** the rule was enforced where the pipeline publishes
and nowhere else. Widening the pattern found **the same stranger's credential
written into four places outside the capture directories** -- a review under
`HISTORY/`, `tests/test_p1.py`, a comment in `src/trackers/exclusion.py`, and
an experiment result. ⭐ **This project was refusing to publish a credential in
one file and printing it in the next**, which is the one-gated-door class with
its own headline refusal on the wrong side.

⚠ **Measured before the widening was applied: the accepted corpus moves by 0**,
because those URLs are already refused by the character check. So the fix was
free of consequence for consumers, which is exactly why nothing had caught it --
the defect was invisible in every count anybody looks at.

**Fixed.** All four redacted, the detector widened at its single definition,
two test vectors added, and `docs/security/secrets.md` carries the class.
⛔ **The credential belongs to a third party and cannot be rotated from here**,
so step 1 of that page's incident order is not available to us; the operator is
told in `PROGRESS.md`.

## Finding 3 -- a file can switch off the dependency gate

**Not on the list, and the worst of the three.** `check-no-third-party-imports.py`
builds its "local" set from filenames under `PACKAGE_ROOTS`. So a file named
a file under `scripts/` named after a package makes importing that package
pass **anywhere in the tree**.

⛔ **Measured, not supposed.** Planting such a file plus the matching
`import` in an experiment returned **exit 0** and printed *"standard library
only. D1 holds."*

⚠ **It is not a regression.** `src` and `.` have been package roots since the
roots existed and carry the same hole; the `scripts` root added this morning
widened it by one directory and is what made it visible. Fixing it rather than
noting it, because a checker that can be silenced by adding a file is the
"allowlist applied to the whole line" row of
[`../../docs/conventions/forbidden-patterns.md`](../../docs/conventions/forbidden-patterns.md)
wearing a different shape.

**Fixed.** A local name that also resolves on `sys.path` **outside** the
repository is now refused rather than resolved -- which one an import would get
depends on path order at runtime, and being ambiguous is the defect.

⭐ **The mutation test needed a second attempt, and the first one was the
interesting failure.** Planting `import requests` proved nothing: nothing
third-party is installed on this host at all, so the guard could not have
fired for a reason unrelated to the guard. A guard that passes because the
world happens to be empty is the "check that passes because a different code
path satisfies it" shape in the lens's own description. Re-run with a
colliding module on `PYTHONPATH` outside the repo: **exit 1, naming
`generate`**; and exit 0 with it removed, which is the negative case the lens
also demands.

## Doors checked and found sound

* **`select()`** -- two callers, one authoritative (`sweep`), one preview
  (`probe-corpus`). Grepped rather than recalled.
* **`_build_query` / `_parse_response`** -- every caller is inside `bep34.py`
  and passes the type explicitly except `lookup()`, which is BEP 34's own path
  and correctly takes the TXT default. `test_txt_is_still_the_default_so_bep34_is_unchanged`
  asserts that default, because if it ever moves every operator's refusal
  becomes invisible at once.
* **`--only-source` is not a gate bypass.** BEP 34 is consulted in `probe_udp`
  and `probe_http`, which are reached however the list was chosen; the
  concurrency, per-host and deadline bounds are `sweep()`'s; and the `ci`
  sample cap still applies on top of the narrowed corpus. An unknown source
  exits 2 rather than probing nothing.
* **`carries_private_credential` had a third caller the list missed** --
  `scripts/generate.py:88`, a publication guard that refuses to publish if a
  credential reaches the output. Widening the pattern makes it **stricter**,
  and the offline generation still emits 1327 with no problems, so the door
  was checked rather than assumed.
